### Changed

- **Every word is a file, as with Apple's `/usr/bin/trash`.** The actions are flags now: `trash --list`, `trash --restore <name> [dir]`, `trash --empty`. `trash list` trashes a file named `list`, so no file name can ever be read as a command, and `--` only ends the options. Scripts that call `trash <paths>` are unchanged; ones that call `trash list`, `restore` or `empty` need the flag. Apple's `-v`/`--verbose` and `-s`/`--stopOnError` work as there.
- **macOS 27 or later.**

### Added

- **Restores what Finder and other tools trashed too.** trash reads macOS's own Put Back record, the one Finder uses, so an item Finder or `/usr/bin/trash` moved goes back where it came from. macOS keeps that record only for the first item a program moves at once, so trash still stamps every item it moves itself; when the two disagree, the stamp written as the item arrived wins. Why, measured, with the sources: `proofs/put-back` in the repository.
- **`trash --check`: does trash work here right now, with nobody needed.** For scripts and agents with nobody at the screen: says whether trash.app is quarantined (a quarantined app's first launch waits on a dialog only a person can answer), whether the Trash can be read, and whether a person is at the screen. Exit 0 means `trash <paths>` works and nothing waits on a person. Call it under a limit: `timeout 10 trash --check`.
- **`--json`** on `--list` and `--check`, a full `--help`, `--version`, and `trash --skill install` for Claude Code and Codex.

### Fixed

- **Nothing waits on a person who is not there.** With nobody at the unlocked screen, `--list`, `--restore` and `--empty` fail at once saying what is missing instead of opening trash.app's permission window, and a relaunch that macOS holds fails within 10 seconds.
